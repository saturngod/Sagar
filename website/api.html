Content Server
REST API

Sagar can share its library, covers and saved chapter translations with a native client on the same local network. This guide covers every endpoint, its request and response, and the rules for syncing translations safely.

Connection and scope

The server is off when Sagar launches. In the library, open Settings → Content server, enter a port and optional login, then choose Start server. The port defaults to 8080; 0 picks a free port. While running, Settings shows the local-network addresses to connect to.

Use the computer's LAN IPv4 address and the port shown in Settings:

http://192.168.1.20:8080

The address and port are examples. The server listens on IPv4 (0.0.0.0). All API routes start with /api/v1 and are case-sensitive. Opening the base address in a browser shows a read-only reader for browsing, searching and reading books (original and translation side by side). It uses the same login and cannot change anything. This API guide is public at /docs and contains no library data.

While running, the server shares the whole Sagar library. It supports browsing books and covers, downloading original EPUBs, and exchanging saved chapter translations. It does not import new books, delete data, overwrite existing translations, run AI, or control the server remotely. There is no discovery, QR pairing, TLS or public hosting.

The server stays on when Settings is closed and stops when Sagar quits. Settings and login are not restored at the next launch.

Authentication and headers

Optional username and password

  • Both empty: authentication is disabled.
  • Both supplied: every API route requires HTTP Basic authentication.
  • Only one supplied: the server refuses to start.
  • The username cannot contain :; neither value can contain control characters.
  • Limits: username 256 UTF-8 bytes, password 1,024 UTF-8 bytes.
  • Credentials are held in memory only. They are never returned or saved.
Authorization: Basic <base64 of UTF-8 username:password>

With curl, --user reader prompts for the password. Add it to every example below when a login is set, including EPUB and cover downloads.

curl --user reader --fail-with-body \
  'http://192.168.1.20:8080/api/v1'

Use a trusted network. Plain HTTP does not encrypt credentials or book content. Without a login, anyone who can reach the server can download books and fill empty translations. Never expose the port to the internet.

Request headers

HeaderUse
AuthorizationRequired on every route when a login is configured
Accept: application/jsonAppropriate for metadata and translation responses
Content-Type: application/jsonRequired for translation PUT bodies

The API is for native clients. Requests carrying a browser Origin or Sec-Fetch-Site header are rejected with 403, even without a login. CORS is not enabled, and Accept does not change the response format.

API responses include:

Cache-Control: no-store
X-Content-Type-Options: nosniff

JSON responses use application/json, but routing and parsing failures can return plain text. Always check the HTTP status before decoding.

Server information

GET/api/v1

No parameters or body.

  "translationPolicy": "fillMissing",
  "htmlFormat": "chapter-body-fragment"
}
FieldTypeMeaning

translationPolicystringfillMissing: existing translations are protected
htmlFormatstringHTML is a chapter body fragment, not a full XHTML document

Library

GET/api/v1/books?q={search}

The optional q parameter filters books by a literal substring of the title or author, compared in Unicode lowercase. Surrounding whitespace is trimmed and an empty query returns all books. % and _ are literal, accents are not folded, and chapter text is not searched. URL-encode the value.

curl --fail-with-body -H 'Accept: application/json' \
  'http://192.168.1.20:8080/api/v1/books'

curl --fail-with-body --get -H 'Accept: application/json' \
  --data-urlencode 'q=မြန်မာ' \
  'http://192.168.1.20:8080/api/v1/books'

The response is an array ordered by most recently updated, then book ID. No books or no matches returns [].

[
  {
    "id": "book-123",
    "sourceSha256": "aaaaaaaa…aaaa",
    "title": "Book A",
    "author": "Author XXX",
    "coverUrl": "/api/v1/books/book-123/cover",
    "sourceLanguage": "en",
    "targetLanguage": "my"
  }
]
FieldTypeMeaning
idstringServer-local book ID, used in later paths
sourceSha256stringSHA-256 of the original EPUB; identifies the book across apps
titlestringSaved title for display
authorstring or nullSaved author, or null
coverUrlstringOrigin-relative cover route, listed even when no cover exists
sourceLanguagestring or nullSaved source language
targetLanguagestringTranslation language; must match exactly on upload

Resolve coverUrl against the server origin and never put credentials in the URL. Match books for sync with sourceSha256 plus targetLanguage, not by title, author or server ID.

Cover image

GET/api/v1/books/{bookId}/cover
curl --fail-with-body \
  'http://192.168.1.20:8080/api/v1/books/book-123/cover' \
  --output cover.image

Returns raw image bytes (not JSON or base64):

HTTP/1.1 200 OK
Content-Type: image/png
Content-Security-Policy: sandbox; default-src 'none'; style-src 'unsafe-inline'

<binary image bytes>

Supported types: PNG, JPEG, GIF, WebP, AVIF, BMP and SVG. Load covers as images only, never as documents.

Sagar returns the custom cover from Book Settings if one is set, otherwise the cover declared in the EPUB. Original covers larger than 4 MiB are not served. A 404 means the book or a usable cover is missing; show a placeholder.

Download a book

GET/api/v1/books/{bookId}/epub
curl --fail-with-body \
  'http://192.168.1.20:8080/api/v1/books/book-123/epub' \
  --output book.epub
HTTP/1.1 200 OK
Content-Type: application/epub+zip
Content-Disposition: attachment; filename="book.epub"

<binary EPUB bytes>

This is the original, unchanged source EPUB, not a translated book. It contains no translations or custom cover. Fetch translations separately from the chapters endpoint.

Verify the file's SHA-256 against sourceSha256 before importing it: a download can fail after the headers are sent. Range requests and resumable downloads are not supported. 404 means the book does not exist.

Chapters

GET/api/v1/books/{bookId}/chapters
curl --fail-with-body -H 'Accept: application/json' \
  'http://192.168.1.20:8080/api/v1/books/book-123/chapters'

Returns chapters in OPF spine (reading) order with any saved translation HTML. A book with no chapters returns []; a missing book returns 404.

[
  {
    "id": "chapter-001",
    "href": "EPUB/Text/chapter01.xhtml",
    "title": "Chapter One",
    "spineIndex": 0,
    "document": {
      "html": "<h1>အခန်း ၁</h1><p>မြန်မာစာ</p>",
      "status": "draft",
      "revision": 3,
      "authored": true
    }
  },
  {
    "id": "chapter-002",
    "href": "EPUB/Text/chapter02.xhtml",
    "title": "Chapter Two",
    "spineIndex": 1,
    "document": { "html": null, "status": "pending", "revision": 0, "authored": false }
  }
]
FieldTypeMeaning
idstringServer-local chapter ID, used in the upload path
hrefstringOriginal XHTML resource path inside the EPUB
titlestringChapter label for display
spineIndexintegerReading-order position, from zero
document.htmlstring or nullSaved translation body HTML, or null
document.statusstringpending, draft, reviewed or skipped
document.revisionintegerSaved revision; send as expectedRevision on upload
document.authoredbooleanSaved through the chapter editor; not a presence or completion flag

Don't treat a chapter as empty from authored: false or its status alone. Protect any non-empty HTML and any skipped (Keep original) choice.

HTML and chapter mapping

  • HTML is a body fragment. Resolve relative image and link references against the chapter's href in the original EPUB; images are not bundled.
  • Preserve IDs, links, inline markup, meaningful whitespace and Unicode text.
  • Treat HTML as untrusted: render it sandboxed, without scripts, privileged APIs or uncontrolled network access.
  • Match chapters by original hash, target language and href, never by label, array index or chapter number. A table-of-contents entry can span several resources, so split such chapters into per-resource fragments before uploading.

Translated chapter IDs

GET/api/v1/books/{bookId}/chapters/translated

A lightweight way to learn which chapters already have translations, without downloading their HTML.

curl --fail-with-body -H 'Accept: application/json' \
  'http://192.168.1.20:8080/api/v1/books/book-123/chapters/translated'
{
  "chapterIds": ["chapter-001", "chapter-003", "chapter-008"]
}

chapterIds lists chapters with saved, non-empty translation HTML, in spine order. A book with none returns {"chapterIds": []}; a missing book returns 404.

  • Drafts are included: presence does not mean the chapter is complete or reviewed.
  • Empty chapters and Keep original choices without content are not included, so still respect statuses from the chapters endpoint.
  • IDs are server-local; keep the href mapping rather than comparing IDs with client IDs.
  • This is a point-in-time view. The fill-only upload check still prevents overwrites.

Upload a translation

PUT/api/v1/books/{bookId}/chapters/{chapterId}/translation

Fills a chapter that has no translation yet. It never replaces existing content, even if the incoming version is newer.

Send Content-Type: application/json. The UTF-8 body may be up to 8 MiB; unknown fields are rejected.

{
  "sourceSha256": "aaaaaaaa…aaaa",
  "targetLanguage": "my",
  "href": "EPUB/Text/chapter02.xhtml",
  "html": "<h1>အခန်း ၂</h1><p>ဘာသာပြန်ထားသော စာသား</p>",
  "expectedRevision": 0
}
FieldTypeRule
sourceSha256stringMust equal the book's original EPUB hash
targetLanguagestringMust equal the saved target language
hrefstringMust equal the chapter's resource path
htmlstringNon-empty body fragment; editor HTML validation applies
expectedRevisionintegerCurrent revision from the chapters endpoint
 
curl --fail-with-body --request PUT \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json' \
  --data-binary @translation.json \
  'http://192.168.1.20:8080/api/v1/books/book-123/chapters/chapter-002/translation'

Imported

{ "outcome": "imported", "revision": 1, "status": "draft" }

Imports are always saved as drafts, never as reviewed, and progress is updated. The source EPUB is never changed.

Skipped

{ "outcome": "skippedExisting" }

Also 200 OK. The chapter already had HTML or a Keep original choice, so nothing changed. Skipping happens before HTML validation, so a skip does not mean the uploaded HTML was valid.

Errors and retries

StatusMeaningWhat to do
404Book missing, or chapter not in that bookRefresh IDs
409 identity_mismatchHash, language or href differsFix the mapping; never guess a destination
409 revision_conflictChapter is still empty but its revision changedFetch chapters again and reconcile
413Body too largeDon't send partial chapters as a workaround
422Empty or rejected HTMLKeep local HTML, report, fix before retrying

Each upload is checked and saved in a single transaction, so concurrent uploads fill a chapter once and later ones skip. If a connection drops, the save may already have succeeded: refresh the chapters before retrying. Repeating a successful upload safely returns skippedExisting.

Errors and limits

Domain errors return JSON. Internal errors are masked and never include book text or file paths.

{
  "code": "identity_mismatch",
  "message": "Request could not be applied. Check book, chapter, language, revision and HTML."
}

Middleware errors include only a code, for example {"code": "unauthorized"}.

StatusCode / causeWhat to do
400Malformed JSON or pathFix the request (may be plain text)
401unauthorizedSend correct credentials
403browser_not_allowedUse a native client without browser-origin headers
404not_found or unknown routeCheck IDs and path
405Unsupported methodUse a documented method
408request_timeoutRefresh saved state before retrying writes
409identity_mismatch, revision_conflictReconcile; never force an overwrite
413Body too largeReport the transfer as unsupported
415Missing or wrong JSON content typeSet Content-Type: application/json
422Invalid fields or translationFix the request or content
500server_error, storage_error, io_errorKeep local work and retry later
503storage_busy, server_busyBack off and retry

Up to eight requests are handled at once. Handlers and body reads time out after 30 seconds (408). EPUB downloads stream after the headers, so set a client-side download timeout too. A timeout does not prove a write was rolled back.

Add-book and sync flow

Add a book from Sagar

  1. Call GET /api/v1 and check apiVersion.
  2. List books and show title, author and cover (placeholder if missing).
  3. Download the EPUB, verify its hash, and import it through the client's normal safe import.
  4. Fetch chapters, map them by href, and copy translations only into empty local chapters.
  5. Save imported HTML as drafts and show the results.

Sync an existing book

Save pending local edits first, then match the book by original hash and target language. Use the translated-IDs endpoint for a quick overview and the chapters endpoint for mappings, statuses, HTML and revisions. Then for each chapter:

Sagar (server)ClientAction
TranslatedEmptySave server HTML locally, only if still empty
EmptyTranslatedPUT local HTML with the server revision
TranslatedTranslatedSkip both, even if they differ
EmptyEmptySkip
Keep original on either sideAnyKeep that choice; don't replace it

The server protects only writes into Sagar; the client must apply its own fill-only and revision checks for downloads. There is no batch or all-or-nothing sync, so partial success is normal and re-running sync fills the remaining chapters. Show downloaded, uploaded, skipped and failed counts, and re-fetch if identities, languages or revisions change during sync.
